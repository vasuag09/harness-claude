# v0.5 — Extract-and-Evaluate (Phase 2, AC-E4)

**Status:** shipped (v0.5.0) · **Owner:** Vasu · **Date:** 2026-06-16
**Builds on:** [v0.3 Eval Loops](./v0.3-eval-loops.md) (AC-E4), [v0.4 Checkpoint Eval](./v0.4-checkpoint-eval.md)
(reuses the `/eval` PASS/FAIL/MANUAL gate pattern), and the v0.3 run-tracing slice
(`.claude/traces/<date>.jsonl`, which this consumes).

---

## 1. Problem

The Stop "candidate pattern" seed (`scripts/hooks/stop-pattern-extraction.js`) only drops a
generic "this session was long, maybe extract a skill" note — it detects nothing, proposes
nothing, evaluates nothing. AC-E4 asks for a real flow: **detect a repeatable workflow →
propose a reusable skill → evaluate the proposal → stage it for human approval**, never
auto-writing a skill (the v0.1 staging rule). This turns continuous-learning from a nag into
a concrete, reviewable artifact, and is the first eval surface that *uses* the trace data
AC-1 captures.

## 2. In scope / Out of scope

**In scope**
- Upgrade the Stop hook to **detect candidate signals** from `.claude/traces/<date>.jsonl`
  (recurring tool/skill subsequences) and write a *structured* candidate to staging.
- New user-invoked **`/extract` skill**: model reads trace + transcript + staged candidates,
  drafts a skill (frontmatter + steps), runs the rubric, writes the proposal to staging.
- New **`scripts/eval/extract-rubric.js`**: deterministic PASS/FAIL/MANUAL gate on a proposed
  draft (mirrors `checkpoint.js` exit contract), with a documented **seam** where the AC-E3
  benchmark plugs in later.
- Dependency-free tests; docs/HOOKS.md + spec status updates.

**Out of scope**
- AC-E3 benchmark agent itself (fork+worktree+diff, pass@k/pass^k) — only its integration
  seam is defined here. AC-E2 continuous eval. Auto-promotion of any skill (forbidden).

## 3. Acceptance criteria

- [x] **AC-X1 (detect):** on a substantial session (≥40 tool calls), the Stop hook reads the
  day's trace and, when a tool/skill subsequence (len ≥2) recurs ≥2×, appends a structured
  candidate (sequence, count, ts, `/extract` pointer) to `.claude/skills-staging/candidates.md`.
  No trace / below threshold → no candidate written; exit 0 either way.
  ```eval
  bash scripts/eval/test-extract.sh
  ```
- [x] **AC-X2 (never auto-write):** neither the hook nor `/extract` ever writes under `skills/`
  (or any live skill dir). All output goes to `.claude/skills-staging/`. *Test:* run the flow,
  assert `skills/` tree is byte-identical before/after.
  ```eval
  bash scripts/eval/test-extract.sh
  ```
- [x] **AC-X3 (propose):** `/extract` produces a skill draft with valid frontmatter
  (`name`, `description`) + numbered steps, written to `.claude/skills-staging/<slug>/SKILL.md`.
- [x] **AC-X4 (evaluate):** `extract-rubric.js <draft>` scores PASS/FAIL/MANUAL and exits
  **0** (all PASS, none manual) · **1** (a FAIL) · **2** (MANUAL remaining / unparseable).
  FAILs on missing frontmatter or near-duplicate of an existing skill name/description;
  MANUAL for the "is this genuinely reusable" judgment.
  ```eval
  bash scripts/eval/test-extract.sh
  ```
- [x] **AC-X5 (E3 seam):** the rubric exposes a documented, inert benchmark hook point
  (a single function/insertion site) where AC-E3 slots in; its absence degrades gracefully
  to rubric + MANUAL (never blocks).
  ```eval
  grep -q 'AC-E3 SEAM' scripts/eval/extract-rubric.js
  ```
- [x] **AC-X6 (self-contained + secret-safe):** pure Node/shell, no companions (mgrep/graph/
  context7), no network. The hook records only classification/sequence (tool & skill names),
  never tool args/commands/content — consistent with AC-1 trace safety.
  ```eval
  bash scripts/eval/test-extract.sh
  ```
- [x] **AC-X7 (opt-in / non-invasive):** the enhanced hook stays best-effort and exits 0
  always (≪ blocking); `/extract` is explicit; no default-pipeline gate calls it; baseline
  behavior unchanged.
  ```eval
  ! grep -q 'extract-rubric' hooks/hooks.json
  ```

## 4. Constraints

- Lean/modular: files <800 lines (target 200–400), immutable patterns, validated inputs.
- Zero new dependencies (pure Node + shell; reuse `_lib.js`).
- Git boundary: no commit/push/branch unless explicitly asked.
- Prove-then-promote: ships opt-in; no default-pipeline change.
- Hook safety: detection is best-effort, failure-isolated, never blocks/slows a tool call.
- No secret capture: sequence = tool/skill names only.

## 5. Open questions (resolved defaults)

1. **Recurrence threshold** → subsequence length ≥2, recurs ≥2× within one session; keep the
   existing ≥40-tool-call substantial-session gate. **Resolved** (tunable constants up top).
2. **Staging layout** → hook appends to `.claude/skills-staging/candidates.md`; `/extract`
   writes a proposal dir `.claude/skills-staging/<slug>/` containing `SKILL.md` (draft) +
   `eval.md` (rubric report). **Resolved.**
3. **Release** → ships as **v0.5.0** (bump `plugin.json` + `marketplace.json` at `/ship`).
   **Resolved.**
4. **Evaluation without AC-E3** → lightweight deterministic rubric now + a defined E3 seam
   (per AC-X5); chosen over deferring evaluation. **Resolved** (user decision).
