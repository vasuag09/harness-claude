# v0.9.0 — Design altitude (PLAN + VERIFY)

Status: **shipped** · Version: 0.9.0 · Type: cross-cutting pipeline enhancement (not a numbered roadmap phase)

## Problem
The PLAN phase had a *system*-design step (`/architect`) but **no product/UX/UI design step**,
and `/architect` itself was thin. For user-facing work, "what should this look like and how
should it behave" had no home — it leaked into `/implement`, where design comes out worst. Goal:
level up the whole **design altitude** of the pipeline (product/UX *and* system) without breaking
the four-phase spine.

## Decision (placement ADR)
**Add design as conditional steps inside the existing phases, not a fifth top-level phase.**
- Alternatives rejected: (a) a new top-level DESIGN phase — breaks the lean four-phase symmetry
  and fires even when irrelevant; (b) decide structure later — the placement was the load-bearing
  call and was resolvable up front.
- Product/UX design is a *planning artifact* (like `/architect`'s ADR), so it belongs **beside
  `/architect` in PLAN**, gated on relevance. Its review counterpart belongs **in VERIFY**,
  parallel to `/security-review`. Design now bookends like security: planned *and* verified.

## In scope (delivered)
- **`/design`** (PLAN) — routes by surface (product UI → product-UI rubric; marketing/brand →
  aesthetic-direction rubric; mobile → the a11y/UX floor + nearest craft rubric), always overlays
  the a11y/UX floor, emits a design brief. Self-skips with a note when there's no user-facing surface.
- **`/design-review`** (VERIFY) — craft + a11y/UX approval-bar gate; severity-tagged findings
  (Blocker/Should-fix/Note); blocks on Blockers; judges by default (rebuilds only when asked).
- **Strengthened `/architect`** (skill + agent) — mandatory do-nothing/simplest alternative,
  explicit NFR trade-offs, failure-degradation; reads architecture-domain cues; grounds via context7.
- **Self-contained design rubrics** — `skills/design/references/{product-ui,aesthetic-direction,
  ux-floor,review-bar,architecture-domains}.md`, the harness's own design standard synthesized from
  established UX/UI craft principles. No external plugin, install, or attribution required.
- **Wiring** — design gate in `harness-plan`; design-review gate in `harness-verify`;
  `rules/workflow.md` diagram + PLAN/VERIFY exit criteria; manifests/README/CLAUDE.md/SKILLS.md/ROADMAP.

## Out of scope
- A fifth top-level phase. · A new design subagent (`/design` orchestrates existing skills). ·
  Phase 4 (lands separately, after this).

## Design approach (from /research)
Surveyed the landscape of UX/UI craft guidance and distilled it into **the harness's own
self-contained rubrics**, organized by surface so `/design` routes between them: product-UI craft
(dashboards/apps), aesthetic-direction (marketing/brand), and a cross-cutting a11y/UX floor that
overlays every surface (incl. mobile). System design reuses the **existing `architect` agent**,
strengthened and wired to in-repo architecture-domain cues + context7. **No new MCP server** — every
asset is a skill or markdown (consistent with Phase 3 killing codegraph for MCP context tax).

## Acceptance criteria
- [x] `/design` produces a brief (human/task/feel, direction, hierarchy, system, floor, states,
  success) on a user-facing feature; self-skips and says so when there's no UI surface.
- [x] `/architect` rubric forces a do-nothing alternative + explicit NFR trade-offs + failure-degradation.
- [x] `harness-plan` runs the design gate (`/architect` and/or `/design`) per relevance, HALTs, states skips.
- [x] `harness-verify` runs `/design-review` for user-facing changes, blocks on Blockers.
- [x] A change needing neither (internal/CLI — e.g. this harness) passes PLAN/VERIFY without either firing.
- [x] Docs reconciled (README/manifests 25→27 + version 0.9.0, CLAUDE.md, SKILLS.md, ROADMAP, workflow.md).
- [x] `check-reference-integrity.sh` passes (new skills added to its SKILLS list; all internal refs namespaced).

## Constraints honored
Four-phase spine unchanged; design steps opt-in/conditional; a11y + touch floor are non-negotiable
(part of the accuracy floor); reuse-first; files <800 lines.
