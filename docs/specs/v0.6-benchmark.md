# v0.6 — Benchmark Agent (Phase 2, AC-E3)

**Status:** verified — pending release (v0.6.0) · **Owner:** Vasu · **Date:** 2026-06-16
**Builds on:** [v0.3 Eval Loops](./v0.3-eval-loops.md) (AC-E3), [v0.4 Checkpoint Eval](./v0.4-checkpoint-eval.md)
(reuses the `checkpoint.js` 0/1/2 gate + `eval` fence as the default scorer), and
[v0.5 Extract-and-Evaluate](./v0.5-extract-evaluate.md) (fills the **R5 benchmark seam**
that v0.5 left inert in `scripts/eval/extract-rubric.js`).

---

## 1. Problem

The harness can verify a change against its spec (v0.4) and propose+stage a learned skill
(v0.5), but it still **cannot measure whether one of its own components actually earns its
keep**. The v0.5 rubric's R5 ("empirical value") is hard-wired to MANUAL because there is no
benchmark. Without this, "does the `/plan` skill / `architect` agent / a proposed skill make
the model measurably better?" stays a matter of opinion — exactly the question Phase 2 exists
to answer.

AC-E3 closes this: a benchmark that **forks an isolated git worktree, runs the same task with
and without a named component, and reports pass@k (works at least once) and pass^k (works on
all k trials)** so a component can be kept or cut on evidence.

## 2. In scope / Out of scope

**In scope**
- New **`scripts/eval/benchmark.js`** — deterministic harness. Runs k trials per cohort
  (`with` / `without` the component) each in a throwaway `git worktree`, scores each trial,
  computes pass@k + pass^k + success-rate per cohort, emits a verdict, and writes a result
  artifact. Component toggling is via an **env contract** the task command honors — the harness
  stays generic and never knows what a "component" is.
- New user-invoked **`/benchmark` skill** — drives a real subagent as the task command for a
  live measurement, then interprets the result and recommends keep/cut.
- **Wire the R5 seam** in `extract-rubric.js` to be **result-driven**: read a benchmark result
  artifact if present → `{ pass }` (real PASS/FAIL); absent → `null` (MANUAL, unchanged). The
  rubric gate stays deterministic, fast, and offline.
- Dependency-free tests (injected fake task commands — zero model cost); `docs/HOOKS.md` is
  untouched (no new hook); spec-status updates on v0.3 + v0.5.

**Out of scope**
- AC-E2 continuous eval. Any default-pipeline change. Auto-promotion of a skill (still
  forbidden — a passing benchmark feeds R5, but R4 + human approval still gate promotion).
- A persistent leaderboard / historical trend store (single-run artifact only this slice).

## 3. Acceptance criteria

- [x] **AC-B1 (fork + isolation + cleanup):** each trial runs in its own `git worktree`
  detached at HEAD; the task cannot see sibling trials; every worktree is removed after the
  run, **including when a trial's task or score command fails** (no leftover worktrees,
  `git worktree list` clean).
  ```eval
  bash scripts/eval/test-benchmark.sh
  ```
- [x] **AC-B2 (with / without toggle):** the harness runs k trials with the component enabled
  and k with it disabled, signalling the task via env (`HARNESS_COMPONENT`,
  `HARNESS_COMPONENT_ENABLED=1|0`, `HARNESS_TRIAL=<i>`). The harness itself contains no
  component-specific logic.
  ```eval
  bash scripts/eval/test-benchmark.sh
  ```
- [x] **AC-B3 (pass@k + pass^k):** per cohort, reports **pass@k** = ≥1 of k trials passed,
  **pass^k** = all k trials passed, plus `successes/k`. A trial passes iff its score command
  (default: the task's own exit code; recommended: `checkpoint.js <spec>`) exits 0.
  ```eval
  bash scripts/eval/test-benchmark.sh
  ```
- [x] **AC-B4 (result artifact + verdict):** writes `.claude/eval/benchmarks/<slug>.json`
  containing both cohorts' metrics and a `pass` verdict. **`pass` is true iff the `with`
  cohort strictly improves reliability without regressing** — concretely
  `with.successRate > without.successRate` **or** (`with.passCaret && !without.passCaret`) —
  else false.
  ```eval
  bash scripts/eval/test-benchmark.sh
  ```
- [x] **AC-B5 (R5 wiring — result-driven):** `extract-rubric.js` R5 reads
  `.claude/eval/benchmarks/<draft-slug>.json` if present and returns `{ pass }` (PASS/FAIL);
  absent/unparseable → `null` → MANUAL (graceful degrade, gate stays deterministic). The
  documented `AC-E3 SEAM` marker is preserved.
  ```eval
  bash scripts/eval/test-extract.sh
  ```
- [x] **AC-B6 (self-contained + safe):** pure Node + `git` + shell; **zero new deps**; no
  network; reuses `_lib.js`. Cleans up worktrees on any failure path. **Never** runs
  `git commit`/`push`/`branch` against the working tree (worktree add/remove only — an
  isolated sandbox), honoring the git boundary.
  ```eval
  bash scripts/eval/test-benchmark.sh
  ```
- [x] **AC-B7 (opt-in / non-invasive):** `/benchmark` is explicit; no default-pipeline gate or
  hook calls `benchmark.js`; baseline behavior unchanged.
  ```eval
  ! grep -rq 'benchmark.js' hooks/hooks.json
  ```

## 4. Constraints

- Lean/modular: files <800 lines (target 200–400), immutable patterns, validated inputs.
- Zero new dependencies (pure Node + shell + `git`; reuse `_lib.js`).
- Git boundary: worktrees are an isolated sandbox; **no commit/push/branch** on the working
  tree, ever. Worktree cleanup is mandatory and failure-isolated.
- Prove-then-promote: ships opt-in; R5 stays MANUAL by default until a benchmark artifact
  exists; a passing benchmark never auto-promotes a skill.
- Determinism in tests: the harness's pass@k/pass^k/verdict math is unit-tested with injected
  deterministic task commands — no model invocation in tests.
