# Spec: Checkpoint eval runner — `eval/` module + `/eval` skill

**Status:** spec · **Owner:** Vasu · **Date:** 2026-06-16
**Builds on:** [v0.3 Eval Loops](./v0.3-eval-loops.md) — fulfills its reserved **AC-E1**
(checkpoint eval) and **AC-E5** (opt-in). Uses the v0.3 run-trace logbook as one possible
evidence source for a check, and complements the existing `/verify` and `/test` gates.

---

## 1. Problem

The harness can trace *what fired* (v0.3) but cannot yet verify *whether the work satisfies
the spec it was built against*. `/test` runs the suite and `/verify` observes behavior, but
nothing ties a change back to its **acceptance criteria** as a gate. Checkpoint-eval closes
that loop: read a spec's ACs, check the work against them, emit a PASS/FAIL report, and block
ship until clean.

---

## 2. Scope

**In scope**
- `scripts/eval/checkpoint.js` — deterministic Node runner. Parses a spec's AC list, runs any
  attached machine-check, emits a per-AC report, gates via exit code.
- `/eval` skill — model-facing wrapper. Locates the active spec, runs the runner, adjudicates
  prose-only (MANUAL) ACs from concrete evidence, blocks ship until all ACs are PASS.
- `scripts/eval/test-checkpoint.sh` — dependency-free fixture/exit-code tests (mirrors
  `test-trace.sh`).
- Docs: this spec's status, plus a row where `/verify` / `/test` are documented.

**Out of scope** (already reserved as v0.3 AC-E2/E3/E4, built later)
- Continuous / interval evals (full suite + lint on a timer).
- Benchmark agent (fork + worktree + diff, pass@k / pass^k).
- Extract-and-evaluate flow (Stop candidate-pattern → staged skill).
- Any wiring into the default pipeline gates or hooks.

---

## 3. Acceptance criteria

- [ ] **AC-1 (parse):** `node scripts/eval/checkpoint.js <spec.md>` parses the AC list — each
  `- [ ]/[x] **AC-… (label):** text` bullet becomes `{id, label, checked, check?}`. Given
  `docs/specs/v0.3-eval-loops.md`, it finds AC-E1…AC-E5.
  ```eval
  node scripts/eval/checkpoint.js --list docs/specs/v0.3-eval-loops.md | grep -q AC-E5
  ```
- [ ] **AC-2 (run checks):** an AC may carry an inline ` ```eval ` fenced block holding one
  shell command immediately after the bullet; the runner executes it, captures the exit code,
  records **PASS** (0) / **FAIL** (≠0). ACs without a fence → **MANUAL**.
  ```eval
  bash scripts/eval/test-checkpoint.sh
  ```
- [ ] **AC-3 (report + gate):** prints a per-AC PASS/FAIL/MANUAL table; exits **0** only if
  zero FAIL *and* zero unresolved-required AC; non-zero otherwise — same exit-contract shape
  as `trace-report.js --assert-namespace`.
  ```eval
  node scripts/eval/checkpoint.js docs/specs/v0.3-eval-loops.md; test $? -eq 2
  ```
- [ ] **AC-4 (/eval skill):** `/eval [spec]` defaults to the latest `docs/specs/*.md`, runs
  `checkpoint.js`, adjudicates each MANUAL AC from concrete evidence, and blocks ship with a
  clear report until all ACs are PASS.
  ```eval
  test -f skills/eval/SKILL.md && grep -q '^name: eval$' skills/eval/SKILL.md
  ```
- [ ] **AC-5 (self-contained + no-leak):** runner is pure Node, reuses `scripts/hooks/_lib.js`,
  needs no companions; a check's output is never printed (FAIL shows exit code + command only);
  tested by a dependency-free `test-checkpoint.sh` (fixtures + exit codes + secret-safety).
  ```eval
  node -c scripts/eval/checkpoint.js
  ```
- [ ] **AC-6 (opt-in / fulfills v0.3 AC-E5):** ships disabled-by-default — not wired into any
  default pipeline gate or hook. Running `/eval` is explicit; baseline pipeline unchanged.
  ```eval
  ! grep -rl "harness-claude:eval" skills hooks scripts 2>/dev/null | grep -qv skills/eval/SKILL.md
  ```

## 4. Constraints

- Lean/modular: files <800 lines, immutable patterns, validated inputs; pure Node, no new deps.
- **No secret leakage (hard invariant):** a check's output is **never printed**. On FAIL the
  report shows only the exit code + the command (committed author text), so the user re-runs it
  to see output. Mirrors the v0.3 trace hook's capture-nothing rule — no truncation gamble.
- **Trust boundary:** ` ```eval ` fences are shell-executed with the user's privileges (same
  trust as the repo's test scripts / build hooks). `--list` is a safe inspect-before-run path
  (parses, never executes). Documented in the runner header and `/eval` skill.
- Git boundary: no commit/push/branch unless explicitly asked.
- Prove-then-promote: opt-in; no default-pipeline change until measured.

---

## 5. Reuse decision (from /research)

- **Adopt (in-repo):** `scripts/hooks/_lib.js` — `sh(cmd, {timeout, cwd})` → `{ok, out, code}`
  is the eval-fence executor (never throws, captures exit code + output, 20s default).
  `trace-report.js` is the CLI template: `parseArgs` → latest-file → report → numeric exit,
  reusing its **0/1/2 exit contract** (0 clean · 1 fail · 2 nothing-to-act-on).
- **Build new (thin):** the markdown AC + ` ```eval ` fence parser and the PASS/FAIL/MANUAL
  gate (~30–40 lines). The conceptual model is proven by **txm** (npm) and **markdown-exec**,
  but neither fits the checkbox-AC + MANUAL-fallback + zero-dep contract — adopting txm would
  mean rewriting specs into its `!test` syntax and adding a dependency.
- **Defer (port from txm later, YAGNI):** allowing an AC to declare a non-zero *expected* exit code.
- **API facts the plan must respect:** `sh().out` is combined stdout+stderr → surface only on
  FAIL, truncated (secret constraint); checks run with `cwd: process.cwd()` + a per-check
  `timeout`; default-spec selection reuses the `latestTrace` glob/sort pattern.
- **Risk:** no new dep (zero maintenance/license risk); only risk is brittle hand-rolled
  markdown parsing → mitigate by pinning the AC grammar to the existing spec format + fixtures.

## 6. Open questions (resolved)

1. **AC → check binding** → inline ` ```eval ` fence immediately after the AC bullet, one shell
   command; no fence → MANUAL. Backward-compatible (existing specs read as all-MANUAL).
   **Resolved.**
2. **Default spec selection** → latest `docs/specs/*.md`, overridable by arg (mirrors
   `trace-report.js` latest-trace). **Resolved.**
3. **MANUAL gate semantics** → the deterministic script never auto-passes a prose AC (lists it
   MANUAL, non-zero if any required AC unresolved); the `/eval` skill must adjudicate each
   MANUAL to PASS/FAIL before declaring the gate clean. **Resolved.**
