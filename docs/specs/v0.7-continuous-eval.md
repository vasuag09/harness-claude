# v0.7 — Continuous Eval (Phase 2, AC-E2)

**Status:** implemented — pending review/release (v0.7.0) · **Owner:** Vasu · **Date:** 2026-06-16
**Builds on:** [v0.3 Eval Loops](./v0.3-eval-loops.md) (AC-E2 — the last open Phase-2 criterion),
[v0.4 Checkpoint Eval](./v0.4-checkpoint-eval.md) (reuses the `checkpoint.js` 0/1/2 gate

---

## 1. Problem

The eval module can gate a change against its spec (v0.4), propose+stage a learned skill
(v0.5), and benchmark whether a component earns its keep (v0.6) — but it has **no way to take
the target repo's overall health pulse on demand**: do the tests and lint actually pass right
now? Today that means remembering each project's bespoke commands and reading scattered output.

AC-E2 closes Phase 2: a deterministic, opt-in **continuous eval** that runs the target repo's
test suite + lint (and any other checks) on demand or after major changes, and emits a single
**pass/fail summary** with a clean exit contract — so "is the repo green?" is one command, on
any project, with a secret-safe persisted record.

## 2. In scope / Out of scope

**In scope**
- New **`scripts/eval/continuous.js`** — deterministic runner. Resolves a list of checks
  (auto-detected with explicit override), runs each via `_lib.sh`-style `execSync`, **streams
  each child's output live to the terminal** (no capture), records per-check
  `{ name, command, pass, durationMs }`, prints a summary, gates with the module's 0/1/2 exit
  contract, and writes a **secret-free** artifact under `.claude/eval/continuous/`.
- **Command discovery = auto-detect + override.** Detect common checks (package.json
  `test`/`lint`/`typecheck` scripts; fall through to known runners / a `Makefile` `test`/`lint`
  target) and let `--cmd '<shell>'` (repeatable) add or fully override the detected set.
  `--list` = show the resolved checks without running (inspect-before-run, mirrors `checkpoint --list`).
- New user-invoked **`/health`** skill (opt-in eval-module skill, sibling of `/eval`,
  `/benchmark`, `/extract`) — drives `continuous.js`, interprets the gate, and reports the pulse.
- Dependency-free tests (injected deterministic fake commands — zero model cost); spec-status
  update on v0.3 (AC-E2 → DONE); `.gitignore` covers the new artifact dir; `CLAUDE.md` notes
  the opt-in skill.

**Out of scope**
- Auto-firing after changes via a hook (the eval module is strictly opt-in / non-invasive — no
  default-pipeline gate or hook calls `continuous.js`). "After major changes" = the user runs it.
- Coverage thresholds / enforcing the 80% floor (that stays the pipeline `/test` skill's job;
  this is a green/red pulse, not a coverage gate).
- Historical trend store / leaderboard (single-run artifact only; latest wins).
- Any default-pipeline behavior change. Capturing or persisting command output (forbidden by
  the secret invariant).

## 3. Acceptance criteria

- [x] **AC-C1 (run + per-check result):** given one or more resolved checks, runs each in the
  target repo and records `{ name, command, pass, durationMs }` per check (`pass` = exit 0).
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C2 (discovery = auto-detect + override):** with no `--cmd`, detects the repo's checks
  (package.json `test`/`lint`/`typecheck`, else Makefile `test`/`lint` targets); `--cmd '<shell>'`
  is repeatable and **replaces** the detected set when present. `--list` prints the resolved
  checks (name + command) and runs nothing.
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C3 (live-stream, capture-nothing):** each child's stdout/stderr streams **live** to
  the terminal during the run; the summary and the JSON artifact contain **only**
  name/command/pass/durationMs — **never captured output**. Proven: a check that prints a secret
  to its output leaves **zero** occurrences of that secret in the artifact file.
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C4 (pass/fail summary + exit contract):** prints a summary line per check
  (`PASS|FAIL  <name>  <dur>` and, on FAIL, `→ re-run: <command>`) plus a gate line. Exit
  **0** = all checks PASS · **1** = any check FAIL · **2** = nothing to run (no checks resolved)
  / target dir missing (mirrors `checkpoint.js` / `trace-report.js`).
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C5 (secret-free artifact):** writes `.claude/eval/continuous/<timestamp>.json` (and
  updates `latest.json`) with the run metadata + per-check results + gate verdict; the dir is
  gitignored. No output, env, or secret material is written.
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C6 (self-contained + safe):** pure Node + shell; **zero new deps**; no network;
  reuses `_lib.js`. A failing or hanging check (per-check timeout) is recorded as FAIL and does
  not abort the remaining checks or crash the runner. **Never** runs `git commit`/`push`/`branch`.
  ```eval
  bash scripts/eval/test-continuous.sh
  ```
- [x] **AC-C7 (opt-in / non-invasive):** `/health` is explicit; **no** hook or default-pipeline
  step invokes `continuous.js`; baseline behavior unchanged.
  ```eval
  ! grep -rq 'continuous.js' hooks/hooks.json
  ```

## 4. Constraints

- Lean/modular: files <800 lines (target 200–400), immutable patterns, validated inputs.
- Zero new dependencies (pure Node + shell; reuse `_lib.js`).
- **Secret invariant (hard):** command output is live-streamed to the tty (same trust as running
  the command yourself) but **never captured** into the summary, the artifact, or logs.
- **Trust boundary:** detected/`--cmd` commands are shell-executed with the user's privileges —
  same trust as the repo's own `npm test` / build scripts.
- Git boundary: read/run only; no commit/push/branch, ever.
- Determinism in tests: pass/fail/gate logic is unit-tested with injected deterministic fake
  commands — no model invocation, no network.

## 4a. Reuse decision (from /research)

- **Port (in-repo):** `scripts/eval/benchmark.js` is a 1:1 structural template — `parseArgs`
  flag helper (adapt to collect **repeatable** `--cmd`), `slugify`, git-repo guard,
  `stateDir(repo, 'eval/<sub>')` artifact dir, `report()` + JSON-artifact write, and the
  exit-code-from-`execSync`-catch pattern all port directly. Reuse `_lib.js`
  (`stateDir`, `fileExists`, `path`, `fs`, plus `toolCmd`/`has` for runner resolution).
- **Reuse (gate contract):** `checkpoint.js` 0/1/2 exit + summary shape (module convention).
- **Build new (only genuinely novel parts):**
  1. **Live-stream runner** — neither `_lib.sh()` (`stdio:['ignore','pipe','pipe']`, captures)
     nor `benchmark.runCmd` (`stdio:[…,'ignore','ignore']`, suppresses) fits AC-C3. Need
     `execSync(cmd, { stdio: 'inherit', timeout })` → `{ pass, durationMs }`: output streams to
     the tty and **never enters a JS string**, so it can't reach the artifact (secret invariant
     enforced structurally). `execSync` throws on non-zero / timeout; catch carries `.status`
     (exit code); a timed-out check = FAIL and the run **continues** (AC-C6).
  2. **Command auto-detection** — parse `package.json` `scripts` for `test`/`lint`/`typecheck`,
     else `Makefile` `test`/`lint` targets; `--cmd` (when present) **replaces** the detected set.
     Small, zero-dep, hand-rolled.
- **Risks: none — zero new deps.** External task runners (`npm-run-all`/`concurrently`/`wireit`/
  `turbo`/`nx`) are runners, not pass/fail gates with a secret-free artifact, and all violate the
  zero-dep rule + capture-nothing invariant. Build-new by porting in-repo patterns is correct.
  No context7 lookup needed (no external API in play).

## 5. Open questions (resolved defaults)

1. **Command discovery** → **auto-detect + override** (`--cmd` replaces the detected set when
   present). Chosen for zero-config ergonomics over a generic injected-command core. **Resolved (user).**
2. **Output handling / secret-safety** → **live-stream to tty, capture nothing**; artifact +
   summary stay secret-free (name/command/pass/duration only). Chosen over capture-nothing-quiet
   (you'd have to re-run to see failures) and tail-on-fail (breaks the capture-nothing invariant).
   **Resolved (user).**
3. **Skill name** → **`/health`** (short, distinct from the pipeline-bound `/test`; "repo health
   pulse"). *Recommended default — confirm or rename at `/plan`.*
4. **`--cmd` semantics** → **replace** the detected set (not merge), so an explicit invocation is
   fully predictable; add detected+extra is out of scope this slice. *Recommended default.*
5. **Per-check timeout** → default 300s, `--timeout-ms` overrides; a timed-out check = FAIL,
   run continues. *Recommended default.*
6. **Artifact location** → `.claude/eval/continuous/<ISO-ish-timestamp>.json` + `latest.json`
   (gitignored, mirrors `.claude/traces/` and `.claude/eval/benchmarks/`). *Recommended default.*
7. **Release** → ships as **v0.7.0** (bump `plugin.json` + `marketplace.json` at `/ship`),
   closing AC-E2 and **completing Phase 2 (5/5)**. *Recommended default.*
