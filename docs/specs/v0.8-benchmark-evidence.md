# v0.8 — Benchmark Evidence Pipeline (public-claims proof)

**Status:** draft — spec · **Owner:** Vasu · **Date:** 2026-06-17
**Builds on:** [v0.4 Checkpoint Eval](./v0.4-checkpoint-eval.md) (reuses `checkpoint.js` as the
per-task scorer) and [v0.6 Benchmark](./v0.6-benchmark.md) (reuses `benchmark.js` worktree
isolation + pass@k/pass^k + env-toggle contract; extends it with cost capture). **Precedes
Phase 3 (Retrieval)** — prioritized above it.

---

## 1. Problem

The harness is public, but its headline claims — "optimizes the SDLC workflow" and "reduces
token cost" — are an **architecture argument with no measured evidence**. `benchmark.js` (v0.6)
can prove a single component's *reliability* uplift, but (a) it captures **no tokens or cost**,
and (b) nothing has ever been run on a fixed corpus and **published** for others to inspect or
reproduce.

This slice closes that: a reproducible A/B that compares the **whole harness ON** (full
spec→plan→implement→verify pipeline + subagent delegation) vs **harness OFF** (single-context
baseline) across a versioned in-repo task corpus, measuring **cost-per-successful-task ($)** and
**reliability (pass@k / pass^k)**, then publishes the methodology + raw data + honest caveats in
`BENCHMARKS.md`.

**Claim discipline (load-bearing):** we lead with **cost-per-success** and **reliability**. Raw
token totals are shown as *supporting data only* — we do **not** claim "fewer total tokens,"
because subagents spend their own tokens and total count may rise. Over-claiming there is the
fastest way to get the project debunked.

## 2. In scope / Out of scope

**In scope**
- **(Phase A) Cost + token capture in `benchmark.js`.** Each trial captures per-trial
  `cost_usd` and token usage (input/output/cache) from a `claude -p --output-format json` run,
  via a sidecar the trial writes to an env-provided path. The artifact gains per-cohort cost
  aggregates (total, mean/trial, **cost-per-success**). Reliability verdict is unchanged.
- **(Phase B) Harness ON/OFF fairness harness + 3-task PoC corpus.** A versioned, in-repo
  corpus of 3 tasks, each with a spec `checkpoint.js` can score. A task-runner script drives
  `claude -p` for the trial, toggling **only** harness scaffolding via the v0.6 env contract.
- **(Phase C) Suite runner + corpus expansion to 8–10 tasks.** `bench-suite.js` runs the
  per-task benchmark across the corpus and aggregates ON-vs-OFF metrics. Corpus spans difficulty
  and **includes ≥1 trivial task where the harness is NOT expected to help** (honest reporting).
- **(Phase D) `BENCHMARKS.md`.** Methodology, a single reproduce command, a raw-data table
  generated from the artifacts, and explicit caveats.
- Offline, dependency-free tests: a **fake `claude`** emitting canned JSON (zero model cost).

**Out of scope**
- Adapting external benchmarks (SWE-bench etc.) — wrong shape; doesn't exercise the pipeline.
- Per-component verdict changes to `benchmark.js` (its reliability verdict stays; cost is
  additive metadata, not a new gate).
- A historical leaderboard / trend store. CI that spends real model budget (corpus runs are
  explicit/manual; CI runs only the offline fake-claude tests).
- Phase 3 Retrieval work.

## 4. Constraints

- Lean/modular: files <800 lines (target 200–400); split `benchmark.js` cost logic out if it
  pushes the file past budget. Immutable patterns; validated inputs.
- **Zero new dependencies** (pure Node + shell + `git`; reuse `_lib.js`).
- **Git boundary:** worktrees are an isolated sandbox; no commit/push/branch on the working
  tree, ever. Mandatory, failure-isolated worktree cleanup (inherit from `benchmark.js`).
- **Determinism in tests:** all pass/cost math is unit-tested with an injected fake `claude` and
  injected task/score commands — no model invocation, no network in the test suite.
- **Reproducibility for outsiders:** the published reproduce command must work from a clean
  checkout with only `claude` + `node` + `git` present; corpus is versioned in-repo.
- **Claim integrity:** no headline token-reduction percentage; cost-per-success + reliability
  only, with caveats stated.

## 5. Open questions (recommended defaults)

1. **Disabling the harness for OFF cohort** → **OFF trial passes `--safe-mode`** to `claude -p`,
   which disables CLAUDE.md + skills + plugins + hooks + MCP + custom agents while keeping **auth,
   model, built-in tools, and permissions working normally**. ON trial passes no flag (full
   harness). Wired into `HARNESS_COMPONENT_ENABLED` (`=1` → no flag; `=0` → `--safe-mode`).
   **Resolved (research + empirical, Phase D pilot).** ⚠️ **`CLAUDE_CODE_SIMPLE=1` / `--bare` was
   tried first and REJECTED:** it forces ANTHROPIC_API_KEY-only auth, so on a subscription login
   it returns "Not logged in" at $0 and the OFF cohort never runs — a silent fairness-invalidating
   failure the 1-task pilot caught. `--safe-mode` strips the same context AND authenticates.
   Trials also run with `--permission-mode bypassPermissions` (the worktree is a throwaway
   sandbox) or headless `claude -p` cannot create files.
2. **Subagent token attribution** → **`total_cost_usd` already rolls up subagent cost** within
   the session — confirmed via the official Agent SDK `ResultMessage.total_cost_usd` (recorded
   as the session total; subagents run in-session). So cost-per-success is automatically
   inclusive. **Resolved (research)** — Phase A spot-checks: a subagent-spawning task should show
   higher `total_cost_usd` than a no-subagent run.
3. **How cost flows trial → aggregator** → trial writes a small JSON sidecar to an env-provided
   path (`HARNESS_TRIAL_OUT`); harness reads it (more robust than scraping stdout). **Default.**
4. **benchmark.js extend vs new file** → extend `benchmark.js` with additive cost fields
   (non-breaking); add a thin `bench-suite.js` for corpus orchestration. **Default.**
5. **Corpus location + versioning** → `benchmarks/corpus/<task>/` (prompt + spec) committed
   in-repo; result artifacts to gitignored `.claude/eval/benchmarks/`. **Default.**
6. **Corpus strategy** → start with **3 PoC tasks** to validate the measurement plumbing
   end-to-end, then expand to **8–10 hand-written** SDLC tasks spanning difficulty (not
   SWE-bench). **Resolved (user).**
7. **Headline claim** → **cost-per-success ($) + reliability (pass@k/pass^k)**; raw tokens
   supporting-only; no token-% headline. **Resolved (user).**
8. **Release** → ships as **v0.8.0**; reconcile README/marketplace/ROADMAP/CLAUDE per the
   release docs sweep at `/ship`. **Default.**
