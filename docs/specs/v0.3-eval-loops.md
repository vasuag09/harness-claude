# v0.3 — Evaluation Loops (Phase 2)

**Status:** in progress · **Owner:** Vasu · **Date:** 2026-06-16
**Builds on:** [v0.2 Reference Integrity & Host Isolation](./v0.2-reference-integrity.md).
v0.2 made the harness's wiring deterministic; this phase adds the machinery to *verify*
that work is good and that each harness component earns its keep.

This release ships the **run-tracing slice** and **specs** the remaining surfaces for
later sessions (ROADMAP principle: prove each piece in isolation before promoting it).

---

## 1. Problem

The harness produces work but has no automatic way to (a) verify outcomes against
acceptance criteria, (b) measure whether its own skills/agents help, or (c) prove that
the v0.2 namespace fix actually takes effect at runtime — the colliding-host smoke test
(v0.2 AC-6) was skipped and remains the **one unverified load-bearing assumption**: does
the model, told to "delegate to the `harness-claude:planner` agent", actually emit
`subagent_type:"harness-claude:planner"`? If it strips the prefix, v0.2 is inert.

A logbook of what *actually fired* closes that gap and is the substrate for every later
eval surface, so it ships first.

---

## 2. Scope

Two surfaces in one `eval/` module:

- **Project layer** — checkpoint evals (verify work vs. acceptance criteria, block until
  fixed) + continuous evals (full test suite + lint on interval / after major changes),
  run against the *target* repo the harness operates on.
- **Harness layer** — benchmarking (fork + git worktree + diff, with/without a component;
  report **pass@k** = works once, **pass^k** = works consistently) + turning the Stop
  "candidate pattern" seed into a real extract-and-evaluate flow.

### Shipped this release (run-tracing slice)

- `scripts/hooks/pre-tool-trace.js` — PreToolUse **match-all** hook. Appends one minimal
  JSONL line `{ts, tool_name, kind, subagent_type?}` per tool call to
  `.claude/traces/<date>.jsonl`. `kind` ∈ {subagent, mcp (`mcp__*`), skill (namespaced),
  tool}. **Never** records `tool_input` args/commands/content → no secret leakage.
  Best-effort, failure-isolated, exits 0 always.
  - **Runtime note (verified against a live transcript):** the subagent-spawn tool is
    named `Task` in stock Claude Code docs but **`Agent`** in this runtime. Subagent
    detection therefore keys on the presence of `tool_input.subagent_type` (with `Task`/
    `Agent` as a name fallback), not the tool name — caught during `/verify`.
- `scripts/eval/trace-report.js` — reader: summary (counts + skills/subagents/mcp fired)
  and `--assert-namespace` (exit 1 if any spawned `subagent_type` lacks `harness-claude:`).
  This is the live proof of the v0.2 fix.
- `scripts/eval/test-trace.sh` — dependency-free fixture/exit-code tests (11 cases).
- Wiring: `hooks/hooks.json` (`pre:tool:trace`), `.gitignore` (`.claude/traces/`),
  `docs/HOOKS.md` row + disk-writes note.

### Out of scope (this release — spec'd, built later)

`eval/` module proper, `/eval` skill, benchmark agent, checkpoint/continuous eval runners,
and the extract-and-evaluate flow. Phases 3–6 of the ROADMAP.

## 3. Acceptance criteria

### Run-tracing slice — DONE (verified by `scripts/eval/test-trace.sh`, 11/11 green)

- [x] **AC-1 (capture):** any tool call appends one JSONL line
  `{ts, type/kind, name/tool_name, subagent_type?}`; none dropped on a normal run.
- [x] **AC-2 (AC-6 closure):** `--assert-namespace` reports the raw emitted
  `subagent_type` and fails loudly (exit 1) if it lacks the `harness-claude:` prefix.
- [x] **AC-3 (summary):** reader prints per-run summary — skills, agents (with namespace),
  MCPs, and counts.
- [x] **AC-4 (self-contained):** trace + reader need no companions (no mgrep/graph/
  context7); pure Node/shell, no network.
- [x] **AC-5 (non-invasive):** hook records a single ~110-byte line per call (≪50ms) and
  degrades silently if the trace path is unwritable.

> **Live AC-6 proof — CONFIRMED (2026-06-16).** Extracted the *real* model-emitted
> `subagent_type` values from this session's transcript (delegations to the code-reviewer
> and security-reviewer) and ran `--assert-namespace` against them:
> both were `harness-claude:code-reviewer` / `harness-claude:security-reviewer` →
> **exit 0, 2/2 namespaced.** The v0.2.0 host-isolation fix is therefore proven effective:
> the model preserves the `harness-claude:` prefix when delegating. (This real-transcript
> check also surfaced the `Agent`-vs-`Task` tool-name discrepancy noted above.)

## 4. Constraints

- Lean/modular: files <800 lines, immutable patterns, validated inputs.
- Git boundary: no commit/push/branch unless the user explicitly asks.
- Prove-then-promote: each surface ships opt-in; no default-pipeline change until measured.
- Hook safety: tracing is best-effort and never blocks/slows a tool call.
- No secret capture: tracing records classification + namespace only, never arguments.
